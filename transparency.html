FridayNext 透明度

最后更新日期：2026年7月28日

本页面公开 FridayTunnel 的安全架构、威胁模型和运营承诺。我们的立场是「别信我，来验我」——所有安全声明都应当可以被独立验证，而不是只能被相信。

核心主张

FridayTunnel 是一根哑管道。数据面从 App 到你自己的 OpenClaw 网关端到端加密，中继不持有会话密钥；附件在客户端加密后才进对象存储。我们在架构上就没有能力读取你的内容——这不是承诺，是结构。

一、数据面加密

隧道

App 与 OpenClaw 网关之间的全部通信（HTTP、SSE 流式、WebSocket）使用 TLS 加密。中继按 TLS 握手中的明文 SNI 字段路由，不终结 TLS——加密的终点是你自己机器上的网关，证书也由你的网关生成。中继看到的是密文字节流。

证书锁定

App 锁定网关证书的公钥（非叶证书哈希）。配对时记录指纹，之后每次连接都校验；不匹配即断开，不降级、不询问。这意味着即使中继被完全攻陷，也无法通过替换证书来解密流量——它拿不到能通过校验的私钥。

附件

公网附件不走中继，走对象存储旁路。文件在客户端用一次性 AES-256-GCM 密钥加密成 FNEA 信封后才上传，密钥经已加密的隧道传给对端。对象存储和控制面只接触密文、密文长度和随机对象标识。信封按 64 KiB 分帧，每帧的附加认证数据绑定帧序号与结束标记，因此截断、重排或篡改任何一帧都会导致解密失败而非静默出错。

二、威胁模型

我们看得到什么

诚实地说，端到端加密不隐藏网络元数据。中继在网络层必然处理：连接双方 IP、连接时间、目标子域名、流量体积、连接结果。基础设施提供商（阿里云）同样能看到这一层。

我们看不到什么

对话内容、提示词、工具调用结果、附件明文与文件名、网关 Bearer Token、Agent 配置、会话历史。

我们做不到什么

  • 解密隧道流量——不持有 TLS 会话密钥。
  • 解密附件——密钥只在配对双方手里，从不上传。
  • 冒充你的网关——App 锁定公钥指纹，伪造证书过不了校验。
  • 篡改消息——TLS 与 FNEA 均提供完整性保护，篡改会导致连接中断或解密失败。

已知残余风险

  • 元数据可见。缓解：不用于画像或广告，不出售，不提供给第三方；日志按下方保留期轮转。
  • 首次连接信任窗口（TOFU）。配对码带证书指纹时直接锚定；没带指纹的旧式配对退化为首连即信，此时若攻击者已控制网络，可能记录到错误指纹。缓解：配对需同时可达网关与控制面；配对完成后全程锁定，指纹变化一律大声失败而非静默接受。
  • 设备丢失。本地会话在 iOS 沙盒内，设备未加锁时可能被读取。缓解：设置设备密码；远程抹除；过期设备授权最多保留 90 天后删除。
  • 中继或控制面被攻陷。攻击者仍读不到内容，但可以拒绝服务、观察元数据或撤销授权。缓解：控制面状态每日备份；你随时可以关掉 FridayTunnel 回到局域网或自建通道，数据零丢失、零锁定。
  • 运营主体为自然人。当前由个人开发者运营，不具备企业级的合规审计与人员隔离。这是我们选择把安全性建立在架构而非信任之上的直接原因。

三、可验证性

已开源：openclaw-fridaynext-channel——运行在你自己网关上的插件，包含 HTTP/SSE/WebSocket 路由、App Attest 校验、隧道管理，以及上文所述附件加密信封的完整实现（src/public-access/attachment-crypto.ts）。加密声明可以直接对着代码核。

尚未开源：iOS 应用、控制面与中继。这是 D29 背书路线里的既定项，尚未完成，我们不把它写成已完成。

四、漏洞披露

发现安全问题请走负责任披露，不要公开提 Issue：

  • GitHub Security Advisory（首选，私密）
  • 邮件 s826135274@icloud.com，主题注明 Security

我们承诺 7 个工作日内首次回复，验证后 90 天内修复或公开说明缓解措施。修复后经你同意可在此页致谢。本项目由个人维护，目前没有漏洞赏金。

五、滥用举报

如果你发现有人利用 FridayTunnel 从事滥用行为（垃圾信息、扫描、钓鱼、代理牟利等），请发送邮件至 s826135274@icloud.com，主题注明 Abuse，并附上涉及的子域名、时间和可观察到的行为。

需要说明的是：由于隧道内容端到端加密，我们只能依据元数据（子域名、流量特征、连接模式）和外部举报来判断，无法通过检查流量内容来核实举报。经核实的滥用会导致对应授权被撤销、隧道被断开。相应地，我们也无法应要求「检查某条隧道在传什么」——那个能力我们没有。

六、政府与执法数据请求

截至本页更新日期，我们未收到任何政府或执法机构的数据请求、保密令或数据留存要求。此声明会随每次更新复核；若它在未来某次更新中消失，请按其字面含义理解。

即便收到合法请求，我们能提供的也只有实际持有的数据：订阅状态、设备授权、隧道元信息、网络元数据、安全审计记录。对话与附件明文不在其中——不是我们拒绝提供，是我们没有。

七、日志与保留期

  • 控制面审计日志按月切分文件（audit-YYYY-MM.jsonl），只记录授权、配额与安全事件，不含对话或附件内容。
  • Web 服务器访问日志每日轮转，保留 14 天。
  • 控制面状态每日打包备份，保留 14 天。
  • 已过期的设备授权与配对记录保留 90 天后删除，用于排查与安全审计。
  • 加密附件由对象存储生命周期规则自动删除，最长不超过 7 天。
  • 附件流量按自然月统计，进入下一周期后清理上一周期计数。

八、限额

限额存在的目的是让隧道够用于聊天，同时无法被当作通用代理牟利：

  • 隧道上限 3 条 / Apple ID。
  • 附件月流量：订阅期 3 GB，试用期 300 MB。下载计入同一计数器但允许超出上限若干倍（重复下载是正当行为），达到硬顶后拒绝。
  • 单个附件对象上限 100 MB。
  • 预签名 URL 有效期 15 分钟。
  • 服务端强制带宽限速。

九、运营承诺

  • 无广告、无追踪——不集成任何第三方广告、分析或行为埋点 SDK。
  • 不训练——不使用你的对话、提示词、工具结果或附件做任何模型训练。
  • 不出售——不出售数据，不提供给广告商，不允许基础设施提供商将其用于画像。
  • 可退出——FridayTunnel 全程可选。局域网连接永久免费，也可自建 Tailscale、反向代理等方案。
  • 优雅收窄——到期或退款后仅停止公网连接，本地会话、附件与网关配置一律不动。

十、第三方审计（触发式）

当订阅收入足以覆盖成本时，我们承诺委托第三方密码学审计机构审查加密实现、密钥管理与访问控制，并完整公开报告，包括发现的问题。在那之前，我们不声称通过任何外部安全认证——上文的开源代码是当前唯一的可验证凭据。
